1. The big picture

1.1 The one-sentence story

The thread running through all four tasks Structure beats size. A network that is built to understand images needs far fewer numbers than one that must learn everything from scratch — and the assignment walks through that idea one piece at a time.

Each task adds one piece:

1.2 The data, once, for the whole assignment

CIFAR-10 is 60,000 colour photographs, each a tiny 32×32 pixels, belonging to 10 classes (aeroplane, car, bird, cat, deer, dog, frog, horse, ship, truck). Each image is $32\times32\times3 = 3072$ numbers — three colour channels per pixel.

50,000 training images 10,000 test images | | +----+-----+ | | | | 45,000 5,000 10,000 TRAIN VALIDATION TEST | | | learn choose settings touched ONCE, at the very end weights (which optimizer, in Task 4 - never before which learning rate)
Why three splits and not two If I pick my settings by looking at a set of images, then those images have secretly helped train the model — my score on them is flattering, not honest. So the validation set takes all the decisions, and the test set stays sealed until there is nothing left to decide. That is why the notebook only reads the test set in one cell, right at the end, and caches the answer so it cannot accidentally be measured twice.

One more setup detail that matters. Every image is normalised: for each colour channel I subtract the mean and divide by the standard deviation,

$$x_{\text{normalised}} = \frac{x - \mu_{\text{channel}}}{\sigma_{\text{channel}}}$$

with $\mu$ and $\sigma$ computed from the 45,000 training images only. Using all 50,000 would leak information about the validation images into the model. The measured values were $\mu = (0.4912,\ 0.4820,\ 0.4464)$ and $\sigma = (0.2472,\ 0.2436,\ 0.2617)$.

If someone asks "why normalise?" Raw pixels run 0–255. Weights get updated by a step proportional to the input size, so huge inputs mean huge, unstable steps. Centring the data near zero with a spread of about 1 makes every input comparable and lets one learning rate work for all of them.

2.1 The idea: learning is just blame assignment

A network makes a guess, and the guess is wrong by some amount — the loss. Every weight in the network shares some of the blame. Backpropagation is the procedure that works out exactly how much blame each weight deserves, and it does so by walking backwards through the network applying the chain rule.

FORWARD image --> Linear --> ReLU --> Linear --> ReLU --> Linear --> loss | BACKWARD dL/dW1 <-- dL/dx <-- dL/dx <-- dL/dx <-- dL/dx <-- dL/dz <---+ "how much is each weight to blame?"

Each layer only has to know two things: how to compute its output from its input (forward), and how to turn "blame on my output" into "blame on my input and on my own weights" (backward). Chain those together and the whole network trains.

2.2 The mathematics — three derivatives

Throughout, $g$ means the gradient arriving from the layer above, i.e. $g = \dfrac{\partial L}{\partial(\text{this layer's output})}$.

(i) The Linear layer

Forward, for a batch of $N$ images: $\;y = xW + b\;$ with $x \in \mathbb{R}^{N\times d_{in}}$, $W \in \mathbb{R}^{d_{in}\times d_{out}}$, $b \in \mathbb{R}^{d_{out}}$.

$$\frac{\partial L}{\partial x} = g\,W^{\top} \qquad \frac{\partial L}{\partial W} = x^{\top} g \qquad \frac{\partial L}{\partial b} = \sum_{n=1}^{N} g_n$$
How to remember it To differentiate a matrix product, multiply by the other factor, transposed. And the shapes only fit together one way — if your dimensions match, you almost certainly have the right formula. The bias was added to every row of the batch, so its gradient is the sum down the rows.

(ii) ReLU

Forward: $y = \max(x, 0)$.

$$\frac{\partial L}{\partial x} = g \odot \mathbb{1}[x > 0]$$

($\odot$ means multiply element by element; $\mathbb{1}[\cdot]$ is 1 where the condition holds and 0 elsewhere.)

Say it in one line ReLU is a gate. Where it let the signal through going forwards, it lets the blame through coming backwards. Where it blocked the signal, it blocks the blame.

(iii) Softmax + cross-entropy, fused into one block

Softmax turns raw scores (called logits) into probabilities that add to 1. Cross-entropy then measures how surprised we are by the right answer. For logits $z \in \mathbb{R}^{N\times C}$ and true labels $y$:

$$L = \frac{1}{N}\sum_{n=1}^{N}\left(\log\sum_{c=1}^{C} e^{z_{nc}} \;-\; z_{n y_n}\right)$$

And here is the result worth remembering, because it is beautiful:

$$\boxed{\;\frac{\partial L}{\partial z} = \frac{1}{N}\Big(\operatorname{softmax}(z) - \text{onehot}(y)\Big)\;}$$
In words: predicted probability minus true probability If the model says 0.7 for the correct class, the gradient on that logit is $-0.3$ — push it up. If it says 0.6 for a wrong class, the gradient is $+0.6$ — push it down. Every messy term of the softmax derivative cancels against the logarithm in cross-entropy. This is why the two are always written as one block, and it is the single most likely thing to be asked about in an exam.
The trap: overflow $e^{z}$ becomes inf for $z$ above about 88 in single precision, and the loss turns into nan. The fix is to subtract the largest logit in each row first: $z \leftarrow z - \max_c z_c$. The softmax is unchanged (the factor cancels top and bottom) but now every exponent is $\le 0$. My code does this on the first line of the forward pass.

The core of it, in about ten lines:

class Linear:
    def forward(self, x):
        self.x = x                  # remember: needed for dL/dW
        return x @ self.W + self.b

    def backward(self, g):
        self.dW = self.x.T @ g      # (in,N)@(N,out) -> (in,out)
        self.db = g.sum(dim=0)      # bias was added to every row
        return g @ self.W.T       # pass blame to the layer below

class MLP:
    def backward(self, g):
        for layer in reversed(self.layers):   # <-- the entire idea
            g = layer.backward(g)

2.4 Part (b) — proving the gradients are right

Two independent checks, which would fail for different reasons, so passing both is strong evidence.

Check 1 — against autograd. Rebuild the identical network with PyTorch's own nn.Linear layers, copy my weights across, and compare.

One detail that catches people out PyTorch stores a linear layer's weight as (out_features, in_features). Mine is (in, out) — the other way round. So both the copy and the comparison need a transpose. Get this wrong and you will think your gradients are broken when they are fine.

Check 2 — centred finite differences. This trusts nothing at all, not even PyTorch. Nudge one weight by a tiny $\varepsilon$ in each direction and measure the slope:

$$\frac{\partial L}{\partial \theta} \;\approx\; \frac{L(\theta+\varepsilon) - L(\theta-\varepsilon)}{2\varepsilon}$$

I use the centred version rather than the one-sided one because its error shrinks like $\mathcal{O}(\varepsilon^2)$ instead of $\mathcal{O}(\varepsilon)$. The number reported is the relative error:

$$\text{rel err} = \frac{\big|\text{analytic} - \text{numeric}\big|} {\big|\text{analytic}\big| + \big|\text{numeric}\big| + 10^{-12}}$$

What I measured

Both checks report the same quantity in the same layout, so they read side by side:

Reference methodWorst rel. errorMedian rel. errorVerdict
autograd$1.0\times10^{-11}$ $2.5\times10^{-16}$match
centred finite differences$3.7\times10^{-9}$ $1.0\times10^{-10}$match
Why autograd's worst relative error looks larger than its median The median relative error against autograd is $2.5\times10^{-16}$ — one unit in the last digit of a 64-bit number, i.e. identical. The worst case reaches $1.0\times10^{-11}$ only because a handful of gradient entries are themselves near zero, where a round-off-sized absolute difference is a large fraction of a tiny value. The largest absolute difference across every tensor is $3.3\times10^{-16}$, which confirms there is no real disagreement. For near-zero entries the median is the honest figure.

Finite differences sit higher, at $10^{-10}$–$10^{-9}$, and that is expected rather than a defect: the subtraction $L(\theta+\varepsilon)-L(\theta-\varepsilon)$ cancels most of the significant digits, setting a noise floor no implementation can beat.
Two things that make a correct gradient look wrong 1. Single precision. Run the same check in float32 and the relative error sits around $10^{-3}$, which looks like a bug. It is not — subtracting two nearly equal numbers destroys most of the digits. That is why the check runs in float64.
2. ReLU's kink. ReLU is not differentiable at exactly 0. If a value sits within $\varepsilon$ of zero, the two nudges land on opposite sides of the kink and that one weight reports a large error even though the code is right.

The important point is the ceiling, not the gap A fully-connected network cannot get much past 50–55% on CIFAR-10 no matter how long you train it or how wide you make it. This is a limit of the architecture, not a failure of the training. Three reasons:
  • Flattening destroys locality. After reshape, the pixel at (5,5) and the pixel at (5,6) are just "input 165" and "input 166". The network is never told they are neighbours and must learn that separately for every pair.
  • No translation invariance. A cat in the corner and the same cat shifted three pixels right are completely different input vectors. The network has to learn each position from scratch.
  • It is wasteful. The first layer alone is $3072\times512 = 1{,}572{,}864$ weights, and it still only ever sees one fixed arrangement of pixels.
This is exactly the gap a convolution closes — and the small CNN in Task 2 reaches 80.4% with twelve times fewer parameters.

2.6 Part (d) — why deep sigmoid networks will not train

Why sigmoid collapses. The derivative of the sigmoid function is

$$\sigma'(x) = \sigma(x)\big(1 - \sigma(x)\big) \;\le\; \tfrac14$$

with the maximum $\tfrac14$ reached only at $x=0$. Backpropagation multiplies by one of these factors per layer. After 9 hidden layers the signal reaching the first layer is scaled by at most

$$\left(\tfrac14\right)^{9} \approx 4\times10^{-6}$$

and in practice far less, because most units sit away from $x=0$ where $\sigma'$ is much smaller than $\tfrac14$. The early layers receive essentially no instruction and stay near their random starting values. This is the vanishing gradient problem.

Why ReLU plus Kaiming initialisation fixes it Two effects cancel exactly:
  • ReLU's derivative is 0 or 1 — it never shrinks what passes through. But about half the units are off at initialisation, which costs roughly a factor of 2 in signal variance per layer.
  • Kaiming initialisation puts that factor back on purpose. It sets $\operatorname{Var}[W] = \dfrac{2}{\text{fan-in}}$ rather than $\dfrac{1}{\text{fan-in}}$. The 2 in that numerator is the ReLU correction.
So the activation function and the initialiser are not independent choices — Kaiming was derived for ReLU. That is why the figure pairs sigmoid with Xavier ($\operatorname{Var}[W]=1/\text{fan-in}$) and ReLU with Kaiming: it is the honest comparison.
A detail worth being able to explain In the ReLU curve, layer 1 has the largest norm, which looks like it contradicts "flat". It does not. Layer 1's weight matrix is $3072\times128$ while every other hidden layer is $128\times128$ — 24 times more entries contributing to the norm. It is a size effect, not a gradient effect.
The 20-second version "Going backwards, each sigmoid layer multiplies the learning signal by at most a quarter. Ten layers of that and the first layer gets nothing — so it never learns. ReLU multiplies by 0 or 1 instead, and Kaiming initialisation compensates for the half of the neurons that are switched off, so the signal survives all the way back. That is why deep networks only started working around 2010."
