5.1 Designing to the budget

Twenty epochs is the binding constraint, and it changes what the right architecture is. A very deep network spends most of a short schedule just getting organised. Task 3(b) showed this directly: at 30 epochs the 56-layer residual network had not caught up with the 20-layer one on validation accuracy (80.78% vs 83.16%).

The design decision, in one sentence Start from depth 20 — the shape that actually worked in Task 3(b) — and spend the remaining parameter budget on width rather than more layers.

Cosine annealing is the one ingredient not inherited from an earlier task. The learning rate follows

$$\eta_t = \frac{\eta_0}{2}\left(1 + \cos\frac{\pi t}{T}\right)$$

decaying smoothly from $\eta_0 = 0.1$ to zero over $T = 20$ epochs. With such a short budget there is no room for a step schedule's long plateaus, and annealing smoothly extracts most of what a longer schedule would give: large steps early to travel far, tiny steps late to settle.

What the ablation is actually for The deliverable is the ranking, not the headline accuracy. It says which design decisions carried weight and which were nearly free. Based on Task 3(a) I expect augmentation to be the largest single contributor, since it was the only method there that prevented memorisation.
Two caveats to state when reporting it Single seed. Run-to-run variation on CIFAR-10 at this scale is a few tenths of a point, so any difference smaller than roughly half a point should be read as "no measurable effect", not a real ranking.

No interactions. A one-factor-at-a-time ablation cannot see interactions — removing two ingredients need not cost the sum of removing each. Task 3(a) showed exactly this: every regularizer helped alone, but all five together were worse than flip+crop by itself.

5.4 The single test evaluation

Why "once" is enforced by code, not by intention Every time a number from the test set influences a decision, it stops being a held-out measure of generalisation and quietly becomes part of the training procedure. Had I run the ablation against the test set, the winning configuration would have been selected using test data and the reported accuracy would be optimistic by an unknown amount.

So the notebook evaluates it in one dedicated cell and caches the answer to results/t4_test_eval.json. Re-running the notebook reads the stored value instead of measuring again. Deleting that file is the only way to repeat the measurement — which is exactly the moment you would be contaminating the estimate.

How to read the test-vs-validation comparison They should land within about a point of each other.
  • Test close to validation → the validation split did its job. It was used for every decision so it is mildly optimistic, but with only five configurations compared the selection bias is small.
  • Test noticeably below validation → that gap is the price of having tuned on validation. Some of the winner's margin was luck. Report the test number either way: it is the only unbiased estimate you have.

6. Explaining this to someone in five minutes

If you have to summarise the whole assignment out loud, this is the order that works. Each step sets up the next.

1. Start with the problem (20 seconds) "CIFAR-10 is 60,000 tiny photos in 10 categories. I had to build networks to classify them — starting from writing the learning algorithm itself by hand, with no automatic differentiation."
2. Task 1 — how learning works (60 seconds) "I implemented the forward and backward pass of every layer myself. The nice result is that softmax combined with cross-entropy has the gradient predicted probability minus true probability — all the messy terms cancel.

I proved it two ways: against PyTorch's autograd, which matched to 16 decimal places, and by nudging individual weights and measuring the slope directly, which matched to 9.

Then I trained it. It got 50.6% — and that is a ceiling, not a bug. Flattening an image into a list of 3072 numbers throws away the fact that neighbouring pixels are related, and that a cat shifted three pixels right is still a cat."
3. Task 2 — how you descend matters (60 seconds) "Same network, different optimizers. On a deliberately stretched valley, plain gradient descent zigzags across it on every single step — 60 out of 60 — because the step size is dictated by the steep direction while the direction you need to travel is the shallow one. Momentum, which accumulates a velocity, halves the zigzag. Adam, which divides each coordinate by its own gradient history, almost eliminates it.

On the real CNN, the learning rate alone moved accuracy from 43% to 80%. The headline is sensitivity: plain SGD swings 29 points across the grid, Adam only 11. That is why Adam is the default when you cannot afford to tune."
4. Task 3 — two different failures (90 seconds) "Networks fail in two ways that look alike but are not.

Too little data. On 5,000 images mine hit 100% on training and 67% on validation — perfect memorisation. Penalising the weights barely helped; it still memorised. What worked was changing the pictures: flipping and cropping so it never saw the same image twice.

Too many layers. I built the same network plain and with shortcut connections, with identical parameter counts. At 56 layers the plain one broke — training loss 200 times worse than its own 20-layer version, despite three times the parameters. That is not overfitting, because the training loss is what got worse. A 56-layer net could copy a 20-layer one by setting the extra layers to the identity, so the ability is there and gradient descent just cannot find it. One line — out = out + x — fixes it: 0.0009 instead of 0.77."
5. Task 4 and the punchline (30 seconds) "Finally I combined everything under a budget: at most 500k parameters and 20 epochs. I spent the budget on width rather than depth, because Task 3 showed depth needs more epochs than I had.

The thread through all of it is that structure beats size. My best model has fewer parameters than the fully-connected network I started with, and is far more accurate — because convolution, shortcuts and augmentation each build in something true about images that the first network had to try to learn from data, and could not."

6.1 The five questions you are most likely to be asked

QuestionShort answer
Why is softmax fused with cross-entropy? Because the gradient simplifies to $p - y$ — the softmax Jacobian cancels against the logarithm. Separately they are both messier and numerically unstable.
Why does Kaiming initialisation use 2/fan-in? Because ReLU switches off about half the units, costing a factor of 2 in signal variance per layer. The 2 in the numerator is exactly that correction. It is derived for ReLU.
Why no $(1-\mu)$ in your momentum? Both conventions exist and are the same algorithm — they differ by a constant $(1-\mu)$ absorbed into the learning rate. I used PyTorch's form because the task required matching torch.optim.SGD. My Adam does use the $(1-\beta)$ form, because Adam is defined that way.
Is plain-56 failing because it overfits? No. Overfitting means low training loss with poor validation. Here the training loss itself is bad, on data it is being fitted to. It is an optimisation failure.
Why does the test set only get used once? Because any decision made by looking at it turns it into training data, and the reported accuracy stops being an honest estimate of generalisation.
